## Root-cause correction

The first conflicting-party probe incorrectly returned `auto_eligible` because
the schema asked DWS for one generic `party_name`; the provider correctly chose
one source, but the local policy could not see the second name. ConsentDocs was
changed to extract `party_name` and `signature_party_name` separately and
compare them with deterministic local logic. The repeated real call then
returned `needs_review` with `party_name=invalid`.

This is the intended safety architecture: DWS extracts and cites facts; local
policy owns the high-stakes decision. A model is never asked to resolve the
conflict silently.
